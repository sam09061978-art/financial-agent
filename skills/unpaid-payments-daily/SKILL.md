# Инструкция

## Цель
Каждое утро обновлять актуальную таблицу **«Неоплаченные заявки»** — список заявок на оплату, по которым деньги ещё не ушли со счёта. Таблица нужна для контроля платежей и приоритизации; остатки ДС, депозиты и проценты в ней не фигурируют (правило владельца процесса).

## Источники данных (4 файла, в корне проекта)

| № | Источник | Период | Формат | Пример имени |
|---|----------|--------|--------|--------------|
| 1 | Банковская выписка (реестр банковских документов, все счета) | предыдущий день (D-1) | `.xls` | `выписка 26.10.2026.xls` |
| 2 | Реестр платежей Компании (обычно за D-1) | D-1 | `.xls` | `Реестр № 2871 от 26.10.2026.xls` |
| 3 | Перечень неоплаченных из 1С | на утро D | `.xlsx` | `неоплаченные на 27.10.2026.xlsx` |
| 4 | Журнал заявок «Список» (с 2022, ~9600 строк) | на утро D | `.xls` | `Список 27.10.2026.xls` |

Если файла не хватает — спросить пользователя, остальные обрабатывать.

## Логика обработки

### Шаг 1. Прочитать файлы
Node + SheetJS (PowerShell заблокирован): `node .claude/scripts/inspect-xlsx.js <файл> [строк]`, `node .claude/scripts/tail-xlsx.js <файл> [n]`. «Список» большой — читать только хвост (последние дни цикла).

### Шаг 2. Сверить выписку
Поступления + списания = контрольный итог файла. Платежи поставщикам разнести по заявкам реестров (сопоставление по контрагенту + назначению платежу). Комиссии банков (РКО, СМС, пакеты) — заявками не оформляются, справочно в отчёт. Депозитные обороты («Овернайт», срочные вклады) — учитываются только в факте выписки, в перечень не включаются.

### Шаг 3. Статусы реестров
«Утвержден» ≠ «исполнен» . Статус «на утверждении» фиксировался со слов пользователя — подтверждать в чате, не из шапки реестра. Реестр может быть исполнен частично — остаток остаётся в перечне под своим реестром.

### Шаг 4. Сверить перечень 1С и снять оплаченные
Платежи по выписке приоритетнее отметок 1С («Оплачен: Нет» при фактической оплате — не ошибка выгрузки, а несинхронность). Контроль: **«Сумма неоплаченных реестров» из шапки реестра = сумма реестровых секций итогового перечня** (остатки всех реестров).

### Шаг 5. Хвост «Списка» — новые заявки
Новые заявки с последнего дня цикла (статусы «На согласовании», «Согласован, Зарегистрирован») — внести в отчёт. Планы оплаты для них — спросить пользователя (пачкой, по контрагентам). Зарплатные заявки (НДФЛ, аванс) — **включаются в перечень** в составе своего реестра ; до этой даты они были вне перечня.

### Шаг 6. Собрать итоговую таблицу (см. формат ниже)
Данные — в UTF-8 JSON (`register-data-*.json`); сборка — `cscript //nologo build-register-…-com.wsf` (Excel COM; шаблон держать ASCII-only). Самопроверка сумм встроена в генератор; независимая проверка файла — `verify-register-*.js` (Node/SheetJS).

### Шаг 7. Отчёт
`finance/daily-archive/YYYY-MM/YYYY-MM-DD-cash-cycle-report.md` по образцу `2026-10-27-cash-cycle-report.md`: источники, сверка выписки, платежи по реестрам, свод секций, контрольные суммы, новые заявки, «Требует решения», вывод.

### Шаг 8. Архив
Копии исходников — в `finance/daily-archive/YYYY-MM/`; из корня исходники перемещать (`rm` через Bash заблокирован → `cp -n` + `mv -f`). Итоговый xlsx остаётся в `finance/daily-cash-cycles/`.

## Формат итоговой таблицы «Неоплаченные заявки»

**Итоговая таблица — это файл «Неоплаченные заявки»** (`.xlsx`, `finance/daily-cash-cycles/YYYY-MM-DD-unpaid-payments-register.xlsx`). Как и ранее, файл выводится в формате **Эксель с формулами и выделениями**:

- «Итого» по каждой заявке, итоги по группам контрагентов, по разделам и **ОБЩИЙ ИТОГ** — живые формулы SUM (по колонкам плановых дат и колонке «Итого»);
- выделения: жирная шапка и строки итогов, заголовки групп контрагентов, светло-серая заливка строки «ОБЩИЙ ИТОГ», **жёлтая заливка строк-заголовков статус-блоков** («УТВЕРЖДЕН» / «НА УТВЕРЖДЕНИИ» / «НА ФОРМИРОВАНИИ» — с 29.10.2026) (заливки встроены в генератор);
- текст заголовков секций — короткий: «Реестр №…» или «Не включен в реестр — на формировании», без сумм и деталей статуса (детали — в отчёт);
- группировка строк Excel «контрагент → заявки» (ветки сворачиваются), автофильтр по шапке, закрепление шапки;
- денежный формат ячеек `#,##0.00`.

### Колонки (обязательные)
| Колонка | Тип | Описание |
|---------|-----|----------|
| `№` | число | Сквозной номер заявки |
| `Реестр платежей` | текст | «№2855 от 23.10.2026» / пусто для без-реестровых |
| `Статус` | текст | Краткий: «В реестре», «На утверждении», «На формировании», «На согласовании» |
| `Контрагент` | текст | Название организации / ФИО |
| `Содержание` | текст | Назначение платежа / номер счёта / договор |
| Колонки плановых дат | число | «26.10.2026», … — сумма попадает в колонку плана; просроченные даты — первыми |
| `Итого` (формула) | число | `SUM` по колонкам дат строки |

### Секции и иерархия (с 29.10.2026 — указание пользователя)
1. **Секции = статус-блоки с жёлтой заливкой**: «УТВЕРЖДЕН», «НА УТВЕРЖДЕНИИ», «НА ФОРМИРОВАНИИ». Под жёлтой строкой статуса — полужирные строки реестров («Реестр №… от …», без заливки), под реестрами — заявки; в блоке «На формировании» — сразу заявки без реестров (независимо от статуса в 1С).
2. **Иерархия**: у контрагента с несколькими заявками — строка-заголовок группы (по реестру, статусу, контрагенту), под ней отдельная строка на каждую заявку (формулы суммы групп над детьми, группировка строк сворачивается).
3. **Итоги**: «Итого по разделу» под каждым статус-блоком, «ОБЩИЙ ИТОГ» последней строкой — всё формулами.
- Генератор: в JSON данные секции = статус-блоки (`title`, `items`); внутри `items` элемент с полем `reghead` + вложенным `items` — строка реестра; старый формат секций-реестров тоже поддержан.

## Запрещено (правила пользователя)

- **Не отслеживать остатки ДС** на р/с (начало/конец дня), **депозиты и проценты** — никаких сверок сальдо, расчетов прогнозов баланса и кассовых разрывов; опираться только на итоговую таблицу перечня (решение владельца процесса 27.10.2026);
- в графе «Статус» — только краткие статусы без пояснений в скобках; детали исполнения реестров — в отчёт, не в xlsx;
- заявки без реестра — единый раздел «Не включен в реестр — на формировании»;
- банковские комиссии и зарплатные заявки заявками не оформляются.

## Правила валидации

### Обязательные проверки
- [ ] Все доступные источники прочтены; недостающий — уточнён у пользователя
- [ ] Сверка выписки: поступления + списания = контрольный итог файла
- [ ] Контроль реестра: «Сумма неоплаченных реестров» = реестровым секциям перечня
- [ ] Итог перечня: прошлый итог − оплачено + новые = текущий итог (объяснить копейки ±0,01)
- [ ] Сумма по колонкам дат = общему итогу
- [ ] Самопроверка генератора + независимая проверка Node/SheetJS пройдены

### Детали для «Требует решения» (в отчёт, не в xlsx)
- Копейные расхождения между 1С и выпиской — фиксировать, не трекать (влияет на итог ±0,01)
- Заявки с наступившим планом, ещё не включенные в реестр — как довести до оплаты
- Старые зависшие заявки («На согласовании» месяцы назад) — разметить неактуальными или обработать

## Команды

### Основной запуск
```bash
# 1. Сборка таблицы «Неоплаченные заявки» через Excel COM (данные в UTF-8 JSON, шаблон wsf — ASCII-only)
cscript //nologo .claude/scripts/build-register-2026-10-27-com.wsf \
  .claude/scripts/register-data-2026-10-27.json \
  finance/daily-cash-cycles/2026-10-27-unpaid-payments-register.xlsx

# 2. Независимая проверка файла (Node + SheetJS)
node .claude/scripts/verify-register-2026-10-27.js
```

Шаблон генератора переиспользуется на новые дни: меняется только JSON данных (название листа «Календарь», заголовки и подписи — из JSON `labels`). Контроль секционных сумм в генераторе универсальный — работает с любым числом секций реестров без правки wsf.
